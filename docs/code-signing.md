# Подпись кода: измеренное состояние и путь решения

## Проблема

Windows с включённым Smart App Control блокирует запуск программы:

> не знает издателя

Это ожидаемое поведение, а не дефект программы. Smart App Control
пропускает только то, где издатель определён цепочкой доверия и
подтверждён репутацией. Файл без подписи издателя не определён вовсе.

## Измеренное состояние на машине

Проверено 4 октября 2026 года, а не предположено:

| Показатель | Значение | Источник |
|---|---|---|
| Статус подписи `Win11CopyDialog.exe` | `NotSigned` | `Get-AuthenticodeSignature` |
| Сертификатов подписи кода в хранилищах | нет | `Cert:\...\My`, `Cert:\...\Root` |
| `signtool.exe` | не установлен | Windows Kits отсутствует |
| Smart App Control | выключен | `CI\Policy\VerifiedAndReputablePolicyState = 0` |
| Правил AppLocker | 0 | `Get-AppLockerPolicy -Effective` |
| Политики SmartScreen | не заданы | `EnableSmartScreen` отсутствует |
| Mark of the Web на артефактах | нет | `Zone.Identifier` отсутствует |

При выключенном Smart App Control программа запускается — это подтверждено
запуском установленной копии. После перезагрузки Windows не даёт вернуть
Smart App Control обратно: вкладки `Включено` и `Оценка` становятся
недоступными. Отключение защиты не является решением — оно снимает
симптом на этой машине и оставляет проблему у всех остальных.

## Решения

### 1. SignPath Foundation — бесплатно, подходит для этого проекта

Репозиторий публичный и под MIT-лицензией, а это ровно условия
бесплатного подписания для open-source проектов. Microsoft прямо
указывает на SignPath Foundation как на вариант для open-source
разработчиков.

Что нужно:

- публичный репозиторий с лицензией — уже есть;
- артефакт собирается из исходников этого репозитория;
- у бинарника проставлены метаданные проекта — `Product` и
  `AssemblyTitle` теперь заданы в `Win11CopyDialog.csproj`;
- каждая подпись подтверждается вручную;
- ключ хранится в их HSM, то есть встраивается в сборочный конвейер.

Заявка: <https://signpath.org>

Ограничение: интеграция рассчитана на сборочный конвейер, а
GitHub Actions в этом репозитории сейчас не запускаются
(настройка на уровне аккаунта). Пока конвейер не включён,
подпись придётся делать вручную через их интерфейс.

### 2. Купить сертификат

Проверка личности, платно, срок действия ограничен. DigiCert,
Sectigo, Certum и подобные. После получения:

```powershell
.\scripts\Sign-Release.ps1 -Thumbprint ОТПЕЧАТОК
```

### 3. Самоподписанный сертификат — НЕ решает задачу

Microsoft отдельно предупреждает: самоподписанный сертификат не
доверен по умолчанию и вызывает строгую блокировку SmartScreen у
любого, кто не установил его вручную. Для публичного распространения
такой сертификат непригоден и блокировку не отменяет.

## Что уже сделано в проекте

- `scripts/Sign-Release.ps1` — подпись с автопоиском `signtool.exe`
  (файл с BOM, кириллица читается корректно в PowerShell 5.1).
- `Product` и `AssemblyTitle` заданы — метаданные, которые
  проверяются при подписи.
- `Smoke.ArtifactSignature` в диагностике печатает честное
  `НЕ ПОДПИСАН`, а не пропускает раздел молча.
- Обновления защищены манифестом `dist/checksums.json`: SHA-256
  сверяется до распаковки. Это защита от повреждения и подмены
  файла, но **не** подтверждение издателя — манифест сам не подписан.

## Порядок проверки после подписи

```powershell
Get-AuthenticodeSignature "Win11CopyDialog\bin\Release\net8.0-windows\Win11CopyDialog.exe"
# ожидается: Status = Valid
```
